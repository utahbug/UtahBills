## Implementation

- A shared 44px Appearance button opens a native modal dialog containing a labeled radio group: Device default, Light, Dark. Keyboard arrows, checked state, Escape, Close and focus return use native semantics. Desktop placement is adjacent to Contact; narrow screens reuse the spare left navigation gutter, keeping Contact on the right and every navigation destination. Only extreme effective widths below 280px need a separate utility row. No route is added or removed.
- Device default follows `prefers-color-scheme`, including changes while the page is open. Explicit Light/Dark overrides it. The validated `utahbills-appearance` localStorage value persists independently in each browser and synchronizes same-origin tabs. Invalid/missing values mean Device default. Denied storage still allows a choice for the current visit, with a truthful save-failure notice.
- A small inline head bootstrap resolves the saved/device setting before the stylesheet or application bundle, with immediate canvas colors and native `color-scheme`. There is no theme transition or delayed initial light render. The application module binds the persistent shared control without changing navigation or legislative rendering.
- Semantic dark variables cover page/surface/text/muted/link/border/focus colors, inputs and native options, menus, dialogs, copy fallback, calendars and selected days, statuses, positive/negative legislative changes, warnings and historical parchment. Dark backgrounds are slate, not pure black. Every existing light color retains its original fallback; the old light variables remain independent.
- No legislative data, source evidence, acquisition/workflow safeguards, Contact destination/subject, domain, DNS or hosting changes. `noindex, nofollow` remains static. Main is the user-requested deployment after focused verification, rather than a separate experiment or new hosting environment.

## CI fractional-header correction

Initial run [40568653149](https://github.com/utahbug/UtahBills/actions/runs/40568653149) passed source integrity and the production build, then the new strict viewport assertion caught the first navigation row slightly above the viewport at 320px / 200% CSS zoom. It did not deploy. Reproduction with the previously verified DejaVu regular/bold fixtures and pinned Chromium measured Bills at y = -0.109375px, with the expected Linux width 61.0625px. The existing collapse calculation divided fractional layout geometry by rounded offsetHeight. Rounding the computed collapse distance down keeps the complete first row visible. The strict visibility assertion remains; control rectangles are now included in failures and three fractional-font-size cases guard the calculation. No data, color palette, acquisition or assertion relaxation accompanies the correction.

The Linux-font sweep also exposed partially obscured background toolbar targets behind the initially nonmodal Appearance panel. Appearance now uses a native modal dialog, making the background inert while choices are open. Escape, Close and backdrop dismissal restore the trigger; the dialog is removed on close so existing route-specific source dialogs and their assertions remain unchanged. Full-page accessibility assertions remain enabled.

Correction validation passed the complete Phase 7A sweep with verified Linux fonts and pinned Chromium, the retained shared-header suite, and the final Edge Appearance suite. Close/backdrop dismissal, native modal background focus exclusion (while allowing browser chrome), and return focus passed. The dynamically created dialog is explicitly text-enlarged in the eight-width matrix. An Edge headless paint issue hid otherwise correctly styled dialog labels; compositing this small surface with translateZ(0) restored visible labels, verified in screenshots, without changing its layout or colors. No redundant full local suite was run; mandatory CI remains required.
