## Acquisition and preservation

[refresh_text.py](../scripts/refresh_text.py) is a separate acquisition step after successful guarded catalog refresh, revalidating the saved catalog before planning any text work. `refresh_catalog.py` and its exact tracking-ID, historical retention, growth and atomic replacement guards are unchanged. The workflow keeps the existing daily schedule and manual-refresh condition; ordinary pushes do not acquire sources.

Only complete XML documents explicitly linked from checksum-verified 2027 metadata qualify: Introduced, PubSub (substitute), Amended (complete amended text), and Enrolled. Parent version, document type, base bill, session, filename and exact official URL must agree. Supported URLs use HTTPS `le.utah.gov/Session/2027/bills/introduced/`, `amended/` or `enrolled/` with exact version filenames; amended timestamps must use the established AV filename form. Query strings, fragments, redirects, mismatched filenames and unsupported patterns are rejected or left unacquired. Enrolled XML must explicitly identify its substitute number. No guessed URLs, historical crawling, PDF conversion or automatic application of amendment instructions occurs. PubAmend/AmdPages remain associated official links, not complete replacement text.

Limits: **12 document candidates/run**, **4 MiB/document**, **15-second network timeout**, at most **two attempts/document** (one-second retry delay for timeouts/connection failures/HTTP 429/5xx), and **240-second scheduling budget** checked before starting a candidate. An in-flight request may finish after that budget. New/unattempted documents come first; oldest attempted pending work then advances ahead of recent failures. Verified documents are revisited when their document metadata changes or after seven days. Conditional ETag/Last-Modified requests avoid downloading unchanged bytes when supported; otherwise identical bytes do not add another source revision. An unannounced same-URL change can remain undetected until its bounded recheck; this is not continuous monitoring.

Original bytes are SHA-256 addressed in `data/text-2027-raw/`, protected against Git line-ending conversion. `data/text-2027.json` retains exact metadata pins, source associations, retrieval times, verified revision history, last response evidence and attempt outcomes. Same-URL revisions are archived evidence, not invented legislative version IDs or separate comparison choices. Source changes append revisions; returning to earlier content is another observed revision, never an inferred substantive/legal change. Validation reuses Phase 4L's proposed-section parser and hash/session/version checks. DTD/entity declarations, malformed XML, unsupported section structures and mismatched identities cannot replace verified text. Downloaded rejected bytes remain evidence, not comparison input. A fatal planning/integrity/write error leaves the previous manifest intact via candidate-file atomic replacement.

The report distinguishes `verified`, `not_retrieved` (including no supported XML), `failed` (network retrieval), `rejected` (validation/URL/format), and `deferred` (budget). Independent `availability` records whether previously verified text remains available despite a failed/rejected/deferred recheck. `lastOutcome`/`lastError` preserve a failed attempt when later work is deferred. Overall `partial` is explicit whenever any current candidate is not verified. No eligible documents yields zero counts, not proof of future coverage.

## Publication, comparison and coverage

Partial success is intentionally publishable after all existing mandatory checks: valid acquisitions and their failure/defer evidence can advance together and subsequent runs resume. The workflow emits a partial warning, preserves `text-refresh.json` in the 90-day refresh-attempt artifact, prints its status/counts in the job summary and stages the text manifest/raw files only when the text step completes. Fatal text-step failures are included in independent refresh-health failure reporting. A successful step/deployment must not be represented as complete text coverage. Existing catalog, Calendar and archive outcomes remain separate.

[version_model.py](../scripts/version_model.py) remains network-free. It validates all preserved verified revisions and exact metadata associations, and supplies the latest valid source for the matching document group to the existing comparison component. Older text is retained with an explicit acquisition qualification after failure. Removed document associations remain archived but are not attached to an unrelated current group. PDF/XML counterparts remain one document group. Two validated documents enable the existing deterministic comparison; unsupported or missing text retains official links and the existing fallback. There is no new interpretation, full formatted reader, public counter or filter.

The generated `data/version-coverage.json` keeps separate bills/resolutions and excludes public requests. It adds grouped text-document counts for links, verified local text, not retrieved, failed, rejected and deferred work, plus last failed/rejected attempt counts. Verified availability can overlap an unsuccessful latest-attempt count; these are separate dimensions. Measure-level comparable coverage remains two or more validated documents. Revisions and report outputs are reproducible from preserved evidence, not live requests. Historical snapshot: 931 bills/85 resolutions with text links; 13 validated documents across five bills; four bills have at least two comparable documents. Grouped text references: 2,898 bill documents and 192 resolution documents. No historical text was acquired.

Recent Activity code is unchanged and does not consume acquisition hashes as events. New document observations remain grounded in successive official metadata snapshots. Neither first text retrieval nor changed bytes create a publication, substantive-change or action claim.
