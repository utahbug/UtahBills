# UI acceptance checklist

Maintained from Phase 7B; updated October 28, 2026 for the owner’s follow-up. This is the continuing source of truth for UI observations and acceptance; [TASK_BACKLOG.md](TASK_BACKLOG.md) remains the authoritative work/priority inventory. Stable IDs are reused, not recreated. Historical phase records describe earlier designs; the latest owner-authorized requirement wins. This list includes prior owner iPhone observations, retained implementations awaiting human acceptance, current defects and deferred UI-facing work. Data-only acquisition/readiness and independent editorial/release gates remain in the backlog.

Stages are distinct: **Implemented** means code exists; **Automated verified** means the identified checks passed; **Awaiting manual acceptance** means real owner/device/AT outcomes are still required; **Accepted** requires an explicit recorded human decision with reviewer, date, device/browser/AT and result. Automated passes and screenshot inspection never imply Accepted. No item is marked Accepted by this batch. Deferred/blocked items have not entered these stages for their unimplemented scope.

Future UI phases must review this file before editing, preserve existing IDs/observations, update evidence and regressions, and record failures/retests rather than deleting issues. Add new stable IDs for distinct findings only. For Phase 7B, the implementation commit is the commit introducing `docs/PHASE7B_VERIFICATION.md` (`git log --diff-filter=A --format=%H -- docs/PHASE7B_VERIFICATION.md`); its verification record and delivery report identify CI/publication outcomes.
