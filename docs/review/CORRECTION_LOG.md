# Substantive correction log

Established October 25, 2026. No entries have been recorded through this process. This is not a claim that earlier development contained no corrections. Existing phase verification records retain that technical history.

Follow the [correction procedure](CORRECTIONS.md). Add an entry only for an evidence-supported substantive correction, after required approval and verification. Preserve original source files, hashes, earlier wording and unresolved disagreements. Do not publish reporter identities or private email contents without permission.

## Entry template (not an actual correction)

- ID / correction date: COR-YYYY-NNN / YYYY-MM-DD
- Affected page, session, bill/tracking ID and exact version:
- Classification and significance: UtahBills error, official-source change, or unresolved source discrepancy; state what was established.
- Before / after wording or behavior (redacted where needed):
- Supporting official links, source passages, preserved paths and SHA-256 hashes:
- Approval role and date; independent review where meaning changes:
- Implementation commit, focused tests, CI and published verification:
- Remaining uncertainty / re-review / final disposition:

Record source changes as source changes, not as admissions of a UtahBills error. An unresolved report stays open in the intake record; never invent a resolved log entry to fill this file.
